# كشف رأس المال — نظام إدارة التجارة

نظام شخصي لخطة 229 يوم (27 سبتمبر 2026 → 13 مايو 2027): من 20,000 إلى 1,000,000 ريال صافي حقوق ملكية.
المواصفات الكاملة في [`PROMPT.md`](./PROMPT.md). النظام للتجارة فقط.

**الحالة:** المراحل الأربع مكتملة ومختبرة. ربط سلة/زد جاهز وينتظر المفاتيح.

## التشغيل محليًا

المتطلبات: Node 22+، PostgreSQL 16 (محلي أو Neon).

```bash
cp .env.example .env          # عدّل القيم (خصوصًا OWNER_* و SESSION_SECRET)
npm install
npx prisma migrate deploy     # إنشاء الجداول
npm run db:seed               # 56 منتج، 33 أسبوع، 5 محركات، البنك 20,000، حساب المالك
npm run dev                   # http://localhost:3000
```

## النشر (Vercel + Neon) — من الجوال

1. **Neon:** انسخ رابطين من صفحة Connection Details: الـ **pooled** والـ **direct** (من غير `-pooler`).
2. **Vercel → Add New → Project →** `capoog/saif`، وضيف Environment Variables:

   | المتغير | القيمة |
   |---|---|
   | `DATABASE_URL` | رابط Neon الـ pooled |
   | `DIRECT_URL` | رابط Neon المباشر |
   | `SESSION_SECRET` | نص عشوائي 32 حرف+ |
   | `OWNER_EMAIL` | إيميل الدخول |
   | `OWNER_PASSWORD` | كلمة مرور (8 حروف+) |

3. Deploy. أمر `vercel-build` بيعمل تلقائيًا: إنشاء/تحديث الجداول ← البيانات الأولية ← البناء.
   البيانات الأولية آمنة مع كل نشر: مش بتكرر حاجة، ومش بتغيّر باسورد المالك لو موجود.
4. بعد أول دخول: فعّل التحقق الثنائي من الإعدادات.

النسخ الاحتياطي اليومي: `.github/workflows/backup.yml` محتاج GitHub secrets `DATABASE_URL_BACKUP` (الرابط المباشر) و `BACKUP_PASSPHRASE` — نسخة مشفّرة AES-256 تتحفظ 30 يوم، بالإضافة لـ point-in-time restore في Neon.

## محرك القواعد (القسم 5)

- **بيعترض قبل الحفظ** (`src/domain/rules.ts` + `src/server/rules.ts`): صفقة/شراء > 25% من رأس المال (السيارات 35% بعد 50 ألف)،
  السيولة تحت 15% أو 5,000، المخزون > 50% (60% لو مغطى بعرابين)، شراء سيارة تحت 50 ألف، وضع الطوارئ تحت 15,000.
  التجاوز بسبب مكتوب، وبيتسجل في سجل التعديلات (`override`).
- **تنبيهات في لوحة التحكم**: خسارة صفقة/شهر، دفعات بطيئة/قديمة/"ضاعف ×2"، إيقاف إعلان منتج، محرك ضعيف، متابعات متأخرة، ذمم متأخرة، حد الضريبة.

## الأدوار

| الدور | يشوف | يدخل على |
|---|---|---|
| المالك | كل شي | كل الشاشات |
| مندوب (sales) | عملاءه وصفقاته وعروضه بس، بدون تكاليف ولا أرباح | صفقاتي، عملائي، عروضي، عمولاتي |
| مستقل (freelancer) | مهامه والمقابل حقها بس | مهامي |

الحسابات تنضاف من **الإعدادات ← المستخدمين**. عمولة المندوب نسبة من صافي العقد، تستحق بعد التحصيل الكامل وتسليم كل طلبات العقد.

## الوكالة والمشاريع

- **الوكالة**: الاشتراك الشهري يتسجل بضغطة (طلب خدمة مسلّم + تحصيل)، والنظام يذكّرك بالمستحق. مهمة المستقل لما تعتمدها تصير مصروف + مستحق له. هامش كل عميل = إيراده − تكلفة مهامه، وتنبيه لو أقل من 35%.
- **المشاريع الكبيرة**: الدفعة المقدمة التزام على الجهة. كل مستخلص يخصم نسبة المقدمة، ولما ينعتمد يصير إيراد (+ ضريبة لو مسجل). هامش الضمان البنكي محجوز: داخل رأس المال لكن مو من السيولة. تنبيه لو المشروع أكبر من 40% من رأس المال أو بدون مقدمة.

## الأنشطة (أضف نشاط بدون برمجة)

**المزيد ← الأنشطة ← أضف نشاط جديد**: مطعم، كافيه، فود ترك، بسطة، متجر، خدمات.
كل نشاط يصير محرك له منتجاته وقيوده وربحه، ويطلع في قائمة الدخل والإغلاق الأسبوعي ولوحة التحكم، ويدخل في رأس المال والهدف.
- **المطعم/الكافيه**: المواد الخام «منتج / مادة» بمخزون FIFO، والصنف اللي ينباع «صنف بمكونات» بوصفة (مثلًا لاتيه = 18 جم بن + 200 مل حليب). كل بيع يخصم المكونات ويسجّل التكلفة الحقيقية.
- **بيع سريع** (`/sell`): اضغط الأصناف ← نقد/شبكة/تحويل ← ينسجل طلب مسلّم ومدفوع.
- **حد رأس المال**: نسبة اختيارية لكل نشاط، وتنبيه لو تعدّاها. **الإيقاف** يخفي النشاط من النماذج الجديدة وبياناته تبقى.

## ربط سلة وزد

الشاشة: **المزيد ← ربط سلة وزد** (فيها الروابط جاهزة للنسخ والخطوات).

| المنصة | الرابط | متغير البيئة في Vercel |
|---|---|---|
| سلة | `https://<موقعك>/api/webhooks/salla` (تحقق Signature) | `SALLA_WEBHOOK_SECRET` = المفتاح السري من سلة |
| زد | `https://<موقعك>/api/webhooks/zid?token=<التوكن>` | `ZID_WEBHOOK_TOKEN` = نص عشوائي تختاره |

- كل طلب ينزل بقناة «سلة / زد»، والحالة تمشي للأمام بس (webhook قديم ما يرجّعها). التسليم يخصم FIFO ويسجل الإيراد.
- المدفوع أونلاين ينسجل عربون على «مدى / Apple Pay» (أو «تابي / تمارا»)، والدفع عند الاستلام يبقى ذمة. الإلغاء بعد الدفع يسجّل استرداد.
- نفس الطلب ما يتسجل مرتين (قفل على السجل + مفتاح فريد).
- المنتج يتربط برمز **SKU** (خانة في صفحة المنتج). رمز ما نعرفه ← «يحتاج ربط» وتربطه من الشاشة بضغطة، والطلب ينعاد لحاله. مخزون ناقص ← «خطأ» وزر «أعد المحاولة».
- الفاتورة الرسمية: لو المتجر أرسل رقم فاتورته، ينحفظ على الطلب. غير كذا تبقى يدوي (`src/integrations/einvoice` جاهز لأي مزوّد).
- الأسعار تنقرأ كما دفعها العميل؛ إعداد «الأسعار شاملة الضريبة» يحدد تقسيم الضريبة. إجمالي المتجر يتكتب في ملاحظة الطلب للمقارنة.

### القرار المعماري الأساسي: دفتر قيود مزدوج

كل عملية مالية (بيع، شراء، مصروف، عربون، مرتجع…) بتسجل قيد متوازن (مدين = دائن) على دليل حسابات ثابت
(`src/server/chart.ts`). رأس المال بيتحسب من أرصدة الدفتر في دالة واحدة (`src/domain/capital.ts`):

```
رأس المال = النقد + المخزون بالتكلفة + الذمم المضمونة (≤ 30 يوم)
          − الالتزامات (موردين، مستقلين، عرابين، قروض)
          − ضريبة محصّلة غير مسددة − مخصص الزكاة
          − رأس مال الشريك (لا يُحسب في الهدف)
```

- **العربون**: كل مدفوعات الطلب على حساب "العملاء" لنفس الطلب. قبل التسليم رصيده دائن = التزام. عند التسليم بيتسجل الإيراد والضريبة وتكلفة FIFO.
- **الضريبة المحصّلة**: حساب التزام منفصل، مش إيراد أبدًا.
- **الحذف**: قيد عكسي + `deletedAt`. الدفتر لا يُعدّل أبدًا، وكل عملية مالية في `AuditLog`.

## قرارات اتاخدت باقتراحاتي (قابلة للتغيير)

| القرار | المطبّق |
|---|---|
| ألوان الحالة | أخضر > +3% · أزرق ±3% · أصفر حتى −25% · أحمر أقل من −25% (من الإعدادات) |
| الضريبة | غير مسجل افتراضيًا → الطلبات بدون ضريبة، وتتفعّل من الإعدادات |
| الزكاة | 2.5% ÷ 12 شهريًا على رأس المال، تتحسب مرة لكل شهر عند الإغلاق |
| رأس المال المستخدم لكل محرك | مخزونه بالتكلفة + ذممه المضمونة |
| هدف اليوم في لوحة التحكم | خطي بين بداية ونهاية هدف الأسبوع، والإغلاق بيقارن بهدف نهاية الأسبوع |
| الدفع عند الاستلام | ذمة لحد ما تسجّل التحصيل من شاشة الطلب |
| الدخول | جلسات في القاعدة + bcrypt + TOTP (بدون Auth.js — أبسط وتحت سيطرتنا) |
| الرسم | مقياس لوغاريتمي لأن المسار أسّي |
